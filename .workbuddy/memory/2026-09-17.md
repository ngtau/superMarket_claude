## 环境坑（本机 Windows，重要）

- 本机**无 Docker、无 Postgres**。可行替代：WSL Debian 内 `apt install postgresql`（约 23 分钟）。
- WSL2 跨系统网络：Windows 连 WSL 内的 Postgres **必须先调用一次 `wsl.exe` 唤醒**，否则
  ECONNREFUSED/ETIMEDOUT。规律：同一条 Bash 命令里先 `wsl.exe -d Debian -- bash -c "true"` 再连就通。
  长跑任务（如 E2E）需另开后台循环 `while true; do wsl.exe ... true; sleep 4; done` 保活。
- Postgres 默认只听 localhost，需改 `listen_addresses='*'` + `pg_hba.conf` 放行，才有稳定 WSL IP 通路。
- **经 `pnpm` 派生的子进程连不上 WSL 的库**，直接 `node` / `./node_modules/.bin/tsx` 可以。
  Playwright 的 webServer 因此改用 `node dist/main.js` + `node vite/bin/vite.js`，不用 pnpm run。
- `playwright install chromium` 直连 >25 分钟未完成，**设置 `HTTPS_PROXY=http://127.0.0.1:7890` 后 3 分钟装完**。
- git 只配了 `http.proxy` 没有 `https.proxy`，`git push` 会直连卡死；
  必须用 `git -c http.proxy=... -c https.proxy=... push`（代理端口 7890）。
- Playwright 每次启动会清空 `test-results`，触发本机批量删除守卫（>50 文件）而报错；
  先用 PowerShell `Remove-Item -LiteralPath ... -Recurse -Force` 清掉再跑。
- 并行对同一文件发多个 Edit 时，后一个可能静默丢失（遇到过两次），改完必须 grep 复核。
- Git Bash 下 `taskkill //PID` 参数会被路径转换破坏，改用 PowerShell 的 `Stop-Process`。
